# Resizing physical-wall-derived measured edges

The original native RED fixture reproduced a real failure: the generic measured
edge edit changed the outline while leaving its physical sources unchanged,
then refused the stale source. The desktop now retains the entered Quantity and
uses an explicit source-aware edge resize intent.

The analytical inverse reconstructs the physical perimeter from the requested
measured outline. A measured arc keeps its signed sweep and chosen anchor;
physical arc sweeps may change as offset joins are trimmed. All eligible current
measured consumers, attached dimensions and qualified appraisal calculations
derive from the final physical geometry. Connected boundary-chain movement and
movement of other related objects remain separate choices. Incompatible fixed
constraints and frozen physical contacts refuse the complete edit atomically.

Command envelope 13 independently reconstructs the perimeter and verifies all
consumer redraws. The exact entered quantity remains in the retained proof.
Native 39 / extraction 37 apply to retained resize commands, including Undo and
deleted histories. Materialized entity-only imports without that command retain
their previous entity/archive floor and cannot claim the absent entered receipt.

Initial integration built successfully and the actual desktop editor passed
four straight/curved, start/end, chain/local and unit-system cases, including
Cancel, Apply, GLA recalculation, atomic Undo/Redo and editable save/reopen.
Additional fixtures exposed an invalid optional measured-stroke setup and a
real inverse-roundoff defect: independently restoring an unchanged physical
wall could break exact endpoint equality with its changed neighbor. Shared
vertex restoration for the new resize path fixes that inconsistency while
preserving old corner replay. Generic cycle validation remains strict.

The transfer packager's supported-version limit also lagged behind the native
reader. Fourteen Python checks verify admission through 39 and future-format
refusal; an actual native39 desktop project was packaged byte-for-byte.

Independent review also identified a saved-proof flag gap: changing only the
related-movement flag could retain explicit dependent edits. The new dialect
now refuses dependent wall, area and measured-stroke edit lanes when movement
is frozen, including stored proofs with recomputed checksums. Mandatory physical
source reconstruction and current consumer redraws remain allowed.

A separate native regression reproduced missing Details edge dimensions for
identified editable areas. The display now reads their authoritative segment
array as well as legacy boundary arrays. Actual resize fixtures check visible
ANSI tenth-foot dimensions beside the recalculated GLA.

Enabling appraisal while an area was already selected exposed a second display
gap. Details now follows that selection when its report becomes configured,
while preserving independently chosen report rows during ordinary refreshes.
The desktop fixture verifies boundary dimensions immediately after Setup and
after the measured edge is resized.

Final Release verification passed all 14 affected native suites in 39.32 seconds
(`green4-check.json`, exit 0); the Release application build also exited 0.
The final four desktop cases cover straight and curved source edges, both
endpoint anchors, local and chain movement, both unit systems, Preview/Cancel,
Apply, updated GLA, Undo/Redo and save/reopen. Root visually reviewed the final
metric curved-edge Details capture and imperial calculation-trace capture.
An earlier core fixture also dereferenced an empty proof on the Redo history
head; it now checks the retained authored revision explicitly before reading
the proof. That fixture defect is distinct from the product roundoff and
Details visibility defects described above.

Final native verification and delivery are recorded in this checkpoint's local

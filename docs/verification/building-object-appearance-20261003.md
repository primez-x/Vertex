# Building-object drawing appearance

APX-ANNO-003 has an accessible physical-object appearance workflow. This is
within the original production scope; it does not complete the whole
requirement or certify the production release.

## Implemented behavior

Double-click a physical object for quick properties, then choose **Drawing
appearance…**, or use its right-click action. The editor shares the existing
area appearance implementation and changes outline/fill, None/Solid/Hatch,
hatch scale, paper line weight and drawing visibility. Reset removes only that
target's override. The control describes its plan/elevation/section and printed
output scope; it is not a shaded 3D material editor.

Defaults come from the complete unoverridden plan projection, including hidden
objects. Accepted overrides apply after physical geometry is generated, to
each retained shape carrying the logical object's identity, including window
glyphs. Measurement annotations retain their separate appearance/visibility
policy. Model geometry, opening relationships, appraisal facts and assets are
unchanged. A hidden physical object remains in Layers; double-clicking its row
opens floating quick properties so it can be restored.

One shared revision-guarded editor preserves existing area anchors and source
records. Unchanged Apply and Cancel create no command. Raw entity extensions,
required-owner policy, opaque state/record/style fields, siblings and absent
legacy optionals survive edits. Duplicate providers, stale modal context,
invalid colors and read-only transitions are refused without a partial edit.
Undo/Redo and native save/reopen retain the accepted appearance.

## Verification

The baseline native fixture built and failed at the missing appearance control.
The Release application and focused native targets subsequently built. The
final object fixture passed actual wall, swinging door and distinct hosted
window editor interactions; retained geometry checks; screen/shared-print/PDF
color observations; late elevation and section projection; exact history and
native reopening; hidden-object recovery through real tree viewport gestures;
reset, source preservation, no-op and refusal checks. Its original file owner
is released before editable reopening. Windows remain offscreen with
WA_DontShowOnScreen, isolated settings and noninteractive error handling.

Existing area appearance, wall-dimension, full wall-measurement and appraisal
Details checks passed. The last production change only removed the numeric
editor's decorative spin buttons; object and area checks were repeated against
that final build. Keyboard stepping and direct numeric editing remain available.
The door fixture was also strengthened to include its real swing geometry.

The first repeated area capture hit an existing task-owned PDF filename.
Inspection confirmed the fixture's no-overwrite capture behavior. An isolated
capture directory resolved that harness collision, and the final check passed;
no application behavior was changed to satisfy it. Earlier evidence is retained.

Root inspected the actual dialog, unselected plan and native PDF captures under
`artifacts/object-appearance-20261003`. The plan and PDF retain independently
colored wall/door and window geometry. The drawing's source dimensions remain
unchanged. This is scoped technical evidence, not user-observed acceptance.

## Remaining scope

The same editor is offered for slab, room, roof, column, beam, stair and railing
geometry, but this delivery's individual native fixtures cover walls and hosted
doors/windows. SVG artwork coloring and independent output-view overrides
remain open, as does full production visual/print qualification. Pinned SVG
bytes and their gradients were not modified. The full production goal remains
active, including Apex compatibility and standards qualification.

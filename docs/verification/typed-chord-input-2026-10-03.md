# Direct chord length and heading

The shared native precision dialog now defaults to Length / heading for the
three chord-based arc methods. Endpoint X/Y remains an explicit alternative.
The feature works in physical Wall drawing, boundary authoring and Measured
lines; accepted inputs retain original quantity and angle expressions and units.
Cancellation does not change accepted preferences. Unit changes reset the input
basis and cannot admit an obsolete modal result.

Standalone receipt 2, boundary schema 4, measured schema/replay 4 and checkpoint 2
opt in when typed chord input is present. Legacy encodings retain their versions.
Native format 31 and extraction 29 include typed provenance in retained history,
archived boundary sources, redraw replacements and original wall input. Known
payload validation remains mandatory even with a future opaque context version.
The endpoint is derived by the existing analytical kernel, not a second stored
geometry authority. Ordered transforms and edits preserve original local input.

## Evidence

The recorded behavioral RED checks rejected the missing typed receipt codec and
the missing actual-D chord controls before implementation. The final Release
build and 21 affected native checks passed. They cover all three constructions
in Imperial/Metric, analytical endpoints/sweeps/lengths, malformed or duplicate
authority, resource rejection, session/recovery Undo/Redo, frame transforms,
physical length edits, native/extraction roundtrips and future-version opacity.

The actual desktop D command places a starting point before a canvas click,
creates a typed measured curve, rotates it through the real canvas control,
edits physical arc length and saves/reopens it. Default Wall D retains a typed
physical wall and its original-frame metadata. A measured semicircle closes with
a straight side, defines an analytical area of pi/2 square metres, and exports
through the native PDF path. Root inspected the native form and area captures.

An independent advisor found archived/replacement reader-floor omissions and a
known wall receipt validation bypass. Both were corrected and independently
reviewed. Storage tests import fresh direct, archived and replacement proofs
without earlier typed history, lower both reader-version markers and recompute
the logical digest; every downgrade is refused as unsupported format.

Project packaging now supports native formats through 31 instead of stopping at
6. Fourteen focused Python checks pass, including future-format rejection. The
actual UI-saved native31 project stages and verifies with one embedded binary
asset. This preserves the complete project bytes and raw asset content; it does
not establish clean-machine qualification.

Logs, registered CTest results, captures and the actual project package are in
`artifacts/typed-chord-input-20261003`. Installed delivery and exact remote commit
verification are recorded separately in its local delivery manifest. CTest has
an explicit Windows native-DLL environment for the new core test.

## Gap check

Typed chord creation, admission, retained inputs, edits/transforms, recovery,
storage versions, extraction, package compatibility and user documentation are
covered by the current diff and scoped checks. The practical checklist adds
U376–U379 and now accurately counts 380 tasks, including U100a. User results
remain Not tested.

Original textual coordinate provenance, nested-hole area definition, actual
native Apex roundtrips, device/application integrations, final ANSI normative
validation, clean-machine offline qualification and the unified production gate
remain incomplete. This is an internal checkpoint, not the complete production
Apex replacement. Public source and perpetual-free distribution remain the
user's current direction.

# Vertex consolidated production delivery plan

This is the user-approved execution plan for the delivery reset. It preserves
the complete [production scope](../production-plan.md) and replaces the dated
plans' per-turn build/package/install cadence. Historical plans retain their
behavior contracts and evidence; they are not parallel current schedules.

## Product exit

One production Windows 11 x64 release covers imperial/metric residential and
light-commercial measurement, appraisal, architectural/remodeling authoring,
editable 3D, coordinated documentation, and optional offline assistance.
Every original Apex requirement, compatibility obligation, modern improvement,
and Pinc adoption requirement passes together. Source remains public
GPL-3.0-or-later; core use requires no account, activation, subscription, or
network. Keep the current native stack and authoritative document model.

The authoritative delivery registry crosswalks 130 original requirements,
13 Pinc additions, 134 comparison operations, 450 user scenarios, and 83 dated
plans. These inventories overlap. Mapping, implementation, focused checks,
installed evidence, and final acceptance are separate states. Neither source
presence nor a validator exit certifies a complete capability.

## Stable workspace and execution

Maintain one permanent checkout, persistent prepared dependencies, one Debug
and one Release application build, one active candidate package/runtime, and
one complete rollback package/runtime. Real user data and recovery stay outside
generated output. Preserve private migration receipts outside public source.

Copy source and Git metadata with dirty/untracked work intact. Compare refs,
status, source hashes and dependency inputs before cutover. Preserve the old
installed checkpoint until the new candidate is checked. Configure fresh
build directories after relocation; never rewrite old absolute CMake caches.
Project-format migration is separately tested with historical/recovery files,
unknown content, failure/rollback, and preserved originals.

The latest instruction requires continuous execution until the full product
exit. Use [progress.md](progress.md) as the durable resumption record without a
goal loop. Reconcile it with Git and actual evidence, and continue the next
unfinished task. Never restart completed work after compaction. Current steering
is source implementation only: do not run builds, tests, probes, native jobs,
launches, packages or installations. When the user resumes qualification, build
affected targets after a meaningful source batch and package only a coherent
human-test candidate or release.
Documentation, status requests and unchanged source do not trigger builds.

Root owns integration, shared controller/commands, format floors, CMake,
generators, migration, Git and native jobs. Delegates receive exclusive paths.
Freeze every source, header, test, script and resource consumed by the current
native job. Independent work outside that input set may continue. Checks use
frozen executable/resource inputs; changed sources require affected rebuilding
before their results apply. One root-owned job runs at a time; silence or a
polling timeout does not permit restarting it.

## Sequence and finite acceptance

Begin D01 acquisition and D02 qualification alongside relocation. Close D03
authority before dependent edits. Deliver the ordinary drawing job, then
parallel geometry/room/appraisal, architectural, exchange/assistance and
distribution work. Each package has a bounded lifecycle fixture with downstream
effects; final qualification confirms their integration rather than discovering
fundamental omissions for the first time.

The first human-test candidate supports drawing/closing a furnished room,
wall length/thickness edits, hosted openings, selection/navigation/transforms,
area appearance/classification, hierarchy, live Details calculations,
save/reopen/history and readable scaled output. It remains a development
candidate, not a reduced production release.

Keep all 450 user scenarios with steps/expected result and Pass/Fail/Blocked/
Not tested, separately from engineering acceptance. Run affected regression
checks after changes and required integration checks; do not repeatedly run
unaffected suites or produce duplicate packages.

Final qualification includes independent geometry/calculation expectations,
residential remodel and multilevel commercial issue sets, original foreign
fixtures/consumers, interrupted recovery/storage failure, physical print scale,
real pen/touch/assistive access at 100/150/200 percent DPI, clean network-denied
installation/use, and one offline rebuild from the delivered source kit.
Retain existing representative workload and performance thresholds.

Freeze candidate source/dependencies/assets/fonts/profiles/payload identity.
Changed inputs invalidate affected evidence. Root reviews technical integration;
the user accepts observed usability corrections. Automated validation cannot
substitute for either complete behavior or human resolution.

Acquire original Apex files/editions/modules, exact caller/device versions,
historical Pinc projects, normative standards, physical devices/printer and
reference hardware. No preferred appraisal host is specified. Freeze the
supported matrix through discovery; unavailable prerequisites are explicit
owner-bound handoffs/stop conditions, never omissions or repeated goal turns.

100 percent means every applicable assertion passes the final candidate with
no unresolved production blocker. Handoff includes public source, build and
dependency kit, notices/SBOM, format/migration/adapter docs, offline help,
installer/portable runtime, distributable fixtures and completed reports.
Report actual accepted work and dependencies; do not infer remaining time from
the historical maturity estimate.

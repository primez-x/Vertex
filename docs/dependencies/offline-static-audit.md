# Offline static import audit

`offline_static_audit.py` reviews the PE import report generated by
`inspect-runtime.ps1`. It applies a narrow rule to the application entry
points (`property-studio.exe`, `property-cli.exe`, and
`property_planegcs.dll`): they may not directly import network transport or
URL libraries such as WinHTTP, WinINet, Winsock, DNSAPI, or Qt Network.

Some third-party libraries can still contain those imports. For example, a Qt
PDF module may carry Qt Network as a transitive runtime dependency even when
the application never uses a network API. The audit reports those names as
`transitive_network_imports_observed` and keeps them separate from the direct
entry-point decision. A direct import or unresolved import fails the audit.

Run it after a Release PE inspection:

```powershell
python scripts/offline_static_audit.py `
  --imports artifacts/runtime/release-imports.json
```

The JSON result is deterministic and records the entry-point paths, direct
network imports, policy set, and observed transitive names. A passing result
is static evidence only. It does not prove dynamic `LoadLibrary` behavior,
network-denied execution, clean-machine installation, registry isolation,
service/entitlement absence, or licensing. Those remain separate production
qualification gates.

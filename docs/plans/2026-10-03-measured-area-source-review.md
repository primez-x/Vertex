# Explicit measured-area source review

An area derived from measured strokes must be reviewable when linework changes its closed faces. The user chooses an actual current face for the retained area; its name, classification, appraisal facts, factors and unrelated metadata survive. Changed topology uses the existing stable-reference mapping/removal review. No automatic classification of newly split faces is permitted.

## Ownership and delivery

- Core worker: optional linework source replacement on boundary redefinition, strict v6 edit codec, same-context semantic source validation, atomic preview/apply/history and regression fixtures.
- Root: native project/exchange version protection, desktop candidate review and preview, Details/context entry points, integration, build, Git and installed delivery.
- All native writers freeze during native build and executable checks. Unrelated local files remain untouched.

## Verification

1. Show the core regression fails before implementation, then verify an explicitly selected split face becomes current and its GLA recalculates while retained facts survive.
2. Reject invented lineage, another context, inactive phase, duplicate face assignment and mixed wall sources atomically.
3. Preserve older codec dialects; protect new proof in native files and retained history from downgraded readers.
4. Exercise the actual native review dialog: candidate choice, outline/calculation preview, Apply/Cancel, stale source rejection, reference decisions, Undo/Redo, save/reopen.
5. Review the integrated diff, run affected checks and format/source-kit contracts, commit/push/ref verify and install a new checkpoint without replacing previous builds.

This closes a specific appraisal workflow gap. It does not certify the full Apex replacement or ANSI compliance.

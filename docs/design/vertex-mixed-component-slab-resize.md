# Mixed component and slab side resizing

This continues the approved directional-resize design. The first interaction
slice joins independent document components and slabs; other mixed families and
typed skylights retain their separate unfinished release requirements.

The native regression on `9e61f314` renders and selects both owners, then refuses
because there is no mixed side frame. The existing component cohort capture,
manufactured preview, dimension review and release fences are retained.

One captured canvas operator is reexpressed through each actual plan/Site frame.
Every selected source participates, regardless of selection order. Analytical
curve bounds define the shared frame and its fixed opposite-edge anchor. Plan
resizing preserves physical height, base elevation, source definitions and all
unrelated payload. Unsupported owners refuse the complete gesture.

Closed Properties dialect39 under command52 composes canonical component
geometry requests7/8/9 with a complete sorted slab resize roster. Slabs use
coordinated leaf4 or actual-source mapped leaf5. Its closed fields are version,
the existing complete source bindings, component_request,
component_identity_reservations, slab_geometry, slab_allocation, empty
room_reviews and phase_room_reviews, and message. Slab allocation is null for
ordinary/proposed-only edits; replacement roles and membership are derived from
the source, while the caller supplies only inspected fresh identity slots.

Each lane independently replays the same captured snapshot. Exact authenticated
catalog contributions compose before one final original-to-final dimension
batch. Existing dimensions, reviewed profile retirements, unchanged unit
associations and fresh copies share the 1000-association limit. Historical
enclosures cannot borrow this authority. Reader262 and extraction260 protect
retained commands, including undone history; opaque metadata cannot raise this
enclosing reader floor.

The controller retains component topology and slab allocations from preview
through release. Provisional dimension suppression has no publication path.
Release consumes provisional tickets, completes explicit profile review and
manufactures a fresh final candidate before one publication. Source, selection,
viewport, presentation, recovery and cancellation changes retire late results.

Root owns controller integration, persistence/lifetime guards, CMake, Git and
native jobs. The core writer owns the closed enclosure, compositor and core
regressions. Build inputs freeze before each root-owned native job.

Qualification checks both owner orders, anchored exact preview/release, curved
and mapped sources, nested/reflected components, ordinary/baseline/proposed
membership, shared catalogs, dimensions and resource boundaries, stale/refused
publication, one-command Undo/Redo, native reopen, retained reader floors and
dimension-review cancellation. Source presence alone does not close these gates.

[delivery progress](../delivery/progress.md). Core source/history/migration
checks and the ordinary Plan gesture pass. Native Site, curved and phase
interaction still require dedicated qualification, as do the remaining mixed
families and typed skylights.

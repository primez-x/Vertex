# Editable independent components through IFC

The supported recovery path is an exact Vertex-authored independent component
cohort. A foreign assembly or metadata without matching physical geometry does
not become editable authoring. Unsupported source remains retained with fidelity
diagnostics. This boundary preserves the broader exchange scope and does not
claim universal IFC reconstruction.

New exports use `_vertex_ifc_assembly_source` version2 on the
`IFCELEMENTASSEMBLY` root. The source contains the original independent instance,
complete catalog, exact expanded profile provenance, authored quantity totals,
material volumes and total geometric volume. Every generated proxy child has a
version1 `_vertex_ifc_assembly_profile` marker that binds it to the actual root,
ordinal and corresponding provenance row. Existing version1 root carriers retain
their historical inert-reference meaning rather than acquiring new authority.

Editable import requires one actual linked IFC project metre-unit assignment,
proper composed placement frames, supported representation context and native
geometry comparison. The complete actual aggregation roster must match the
expected profile roster, with unique parent and child identities. Each physical
child must agree with its regenerated native solid and source provenance. Nested,
reflected and affine-mapped source profiles retain their authoring; a mesh alone
never supplies an editable profile. Work limits apply before decoding and native
regeneration, across the whole operation including refused candidates.

A successful cohort produces one detached independent root and one private
catalog atomically. The private catalog retains actual types and materials but
has no embedded instances or active foreign document context. Root and catalog
use importer-local document IDs; catalog-local type, part, material and profile
IDs retain their own namespace. Original organization, phase, levels and opaque
extensions remain source provenance. A failed cohort contributes neither partial
authoring nor a subset of consumed children.

The worker-response boundary separately admits these detached catalogs and
independent roots, requires one root per private catalog, preflights every raw
catalog before semantic decoding, and uses a shared expansion budget. Detached
Document validation checks the complete graph. The desktop remaps the two
document identities together, assigns the selected drawing context to the root,
and commits the complete import and retained source asset in one command.

Source implementation is not production qualification. Required observation
includes straight and mapped curved profiles, nested/reflected nodes, materials
and quantity agreement, complete/missing/duplicate/mismatching children,
placement/context/unit refusals, shared work exhaustion, worker admission,
destination remapping, cancellation, Undo/Redo, save/reopen and source retention.

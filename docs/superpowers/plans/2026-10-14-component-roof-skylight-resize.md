# Component, whole-roof and different-host skylight resize plan

Outcome: one source-bound side gesture and Undo for all three semantic rosters,
using new Properties45/reader268/extraction266 without changing historical proof.
See [the contract](../../design/vertex-component-roof-skylight-resize.md).

1. Native writer owns new tests/mixed_component_roof_skylight_resize_desktop_tests.cpp.
   Build a real independent component, ordinary schema1 roof and typed skylight
   on a different unselected schema4 host with a real untouched sibling. Admit
   native source bounds/ink, authenticated controls, exact semantic rosters and
   source preservation across six orders before the MissingFrame RED.
2. Root registers and runs that native RED. No source implementation begins until
   the actual failing behavior is captured. The flat fixture is no slope claim.
3. Core writer owns mixed_selection_property_edit and phase_constraint_authoring
   header/source pairs and tests/mixed_component_roof_skylight_resize_tests.cpp.
   Write useful regressions, add the closed13-field bridge and one aggregate
   analytical capture preflight. Extract the private roof contribution, combine
   it with the existing child contribution from the same original map, then use
   the unchanged two-candidate finalizer once. Preserve39..44 and roofv1/v2.
4. Root owns controller, Document/lifetime, reader268/extraction266, CMake, docs
   and generators. Add combined dispatch/source-only admission, exact two-roster
   review/release comparison, correspondence and retained target inventories.
5. Native writer extends its exclusive fixture for Plan/Site, both axes/anchors,
   preview/commit/output, one Undo/Redo, review/Cancel/stale fences and fresh Open.
   Core qualifies pitched/yawed/rotated cases, receipts, shared catalogs and
   dimension batches, units, disjointness/exclusions, aggregate bounds, freshness
   and native/extraction/old-reader persistence with opaque controls.
6. Root freezes consumed inputs for each native job, integrates returned ownership
   and reviews the exact source/composition boundary. Use one read-only independent
   challenge if the new multi-contribution composition leaves consequential risk.
7. Fix required findings, run focused/historical and Release/standard/protected/
   smoke gates, inspect changed Plan/Site captures, refresh tracked source-kit
   inventory and both diff checks, then scoped commit/push/exact remote verification.

No routine approval gate is added. Writers run no native jobs/builds/tests, Git,
generators or external mutations. Root owns integration and verification. Same-host
roof/skylight authority and other physical-family combinations are excluded here.
